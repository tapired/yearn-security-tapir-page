# Security Review — Aave V4 Lender Borrower (Issue #774)

## [Medium] First-borrow APR projection omits Aave’s risk premium

### Details

`getNetBorrowApr()` projects the post-borrow Hub rate but applies the strategy’s current risk premium. With collateral and zero debt, Aave reports zero risk premium; `Spoke.borrow()` adds debt and then installs the collateral-derived premium. The strategy can therefore approve a first borrow whose actual cost exceeds the lender APR. `StrategyAprOracle` has the same zero-debt discrepancy.

This is source-confirmed against the prepared Aave implementation. Live collateral-risk values and rates were not available.

### Recommendation

Project the post-borrow risk premium, using the collateral risks Aave will apply after refreshing the account. Add a zero-debt test where lender APR lies between the base and premium-adjusted borrow rates, covering both leverage execution and `aprAfterDebtChange()`.

## [Medium] Reports and tends can re-leverage after shutdown

### Details

Tokenized Strategy intentionally leaves `report()` and `tend()` callable after shutdown. Both target hooks can call `_leveragePosition()` without checking `isShutdown()`. Consequently, a keeper can resupply collateral, borrow USDC, and relend it after `emergencyWithdraw()` has recovered capital, defeating the emergency wind-down.

The existing shutdown tests do not call report or tend after emergency withdrawal.

### Recommendation

After shutdown, allow only conservative accounting and debt settlement; never supply, borrow, or lend. Add regressions that shutdown, emergency-withdraw, then call report and tend and prove no Aave position is reopened.

## [Medium] Withdrawal limits ignore Aave liquidity and exit restrictions

### Details

`availableWithdrawLimit()` begins with the strategy’s full collateral balance and considers lender liquidity, but not the collateral Hub’s liquid assets, reserve pause, or Spoke active/halted state. Aave’s exact implementation does not partially fill: `Spoke.withdraw()` reaches `Hub.remove()`, which reverts on insufficient liquidity or disabled Spoke status. Where deleveraging is required, a paused debt reserve also prevents repayment.

Thus `maxWithdraw()` and `maxRedeem()` can advertise exits that revert, including through a parent Vault withdrawal queue.

### Recommendation

Limit collateral availability by current Hub liquidity and all relevant reserve/Spoke flags. Model whether the requested exit requires repayment and whether that repayment is executable. Test liquidity exhaustion, pause, halt/inactive status, and paused-debt deleveraging.

## [Medium] The proposed configuration disables negative-carry safeguards

### Details

`forceLeverage` defaults to true, and the proposed deployment script explicitly retains it. In this mode borrow APR is reported as zero and lender APR as one, so leverage cannot be rejected or unwound by the profitability checks. The included test confirms that enabling the flag suppresses tending after rewards become unprofitable.

The strategy can therefore retain a losing carry trade, contrary to the issue’s claim that it will sit only on collateral when rates become unprofitable. No final-source deployment of this configuration was proven.

### Recommendation

Deploy with `forceLeverage` disabled unless an equivalent governed controller enforces carry safety. Add a deployment regression that creates negative total carry and proves new borrowing is prevented and existing leverage becomes eligible to unwind.

## [Low] Aave restrictions can make accounting reports attempt forbidden actions

### Details

Although `availableDepositLimit()` returns zero when Aave supply or borrowing is disabled, `_harvestAndReport()` still settles debt and calls `_leveragePosition(0)`. An under-target position can compute a positive borrow, while a lender/debt shortfall can trigger repayment. Prepared Aave code rejects paused repayment and paused, frozen, non-borrowable, inactive, or halted borrowing, causing the accounting report to revert.

### Recommendation

Separate conservative reporting from position adjustment. When an Aave action is unavailable, skip that action and report the existing collateral, lender claim, loose balances, and debt accurately. Test both under-target borrowing and debt-shortfall repayment during pauses.

## [Low] Add-cap rounding overstates capacity by one unit

### Details

The strategy calculates collateral headroom using `getSpokeAddedAssets()`, which rounds existing Aave shares down. Hub add-cap enforcement rounds the same shares up. At the cap boundary, `maxDeposit()` can therefore advertise one smallest asset unit more than Aave accepts, causing an exact-max deposit or report resupply to revert with `AddCapExceeded`.

### Recommendation

Compute used capacity with the same upward rounding as Hub enforcement, or subtract a conservative unit. Test accrued share prices where upward and downward conversions differ and exercise both exact-max deposits and report-time resupply.

## [Low] Stale dynamic collateral configuration can invalidate strategy sizing

### Details

The strategy sizes leverage and withdrawals using the position’s stored Aave dynamic configuration. Aave supply preserves that historical key, but borrow and collateral withdrawal refresh to the latest key before validating health. After governance lowers the collateral factor, the strategy can size an action using the old factor and have Aave revert it after refresh.

Aave prevents unsafe debt, but deposits, reports, tends, or withdrawals can lose liveness.

### Recommendation

Size every risk-increasing action against the current reserve configuration and avoid the action when the refreshed position would be unhealthy. Add tests for a materially reduced collateral factor followed by borrowing and withdrawal.

## [Low] Collateral APR omits gross Aave premium-share accrual

### Details

The APR oracle calculates collateral supply yield using current total owed, which contains drawn debt plus net premium debt. Aave premium shares begin accruing with the drawn index immediately, while an offset initially makes their net premium debt zero. The actual supplier-accrual weight can therefore exceed the oracle’s numerator, conservatively understating collateral-side APR.

### Recommendation

Calculate supplier accrual from gross drawn and premium-share exposure at the current index, net of the liquidity fee. Compare the oracle against observed added-asset growth in an Aave fixture with nonzero premium shares.

## [Informational] Illiquid lender-profit accounting remains unverified

### Details

When lender assets exceed Aave debt, `_settleDebt()` can redeem only the lender’s current `maxRedeem()`. Any inaccessible excess is then omitted because final accounting subtracts only net debt and does not include positive lender claims. If the intended yvUSD becomes illiquid, previously earned profit—or principal remaining after debt repayment—could be absent from `totalAssets` until liquidity returns.

Generic Vault V3 permits partial `maxRedeem`, but the exact yvUSD runtime, withdrawal queue, and live configuration were not prepared, so occurrence is unresolved.

### Recommendation

Test the intended yvUSD with `convertToAssets(balance) > debt` and zero or partial `maxRedeem()`. Confirm reporting includes the recoverable net claim and does not transfer old gains to later depositors when liquidity returns.

## [Informational] Deployment and external implementations remain unverified

### Details

The issue’s deployment table remains `TBD`. Prepared evidence does not link the reviewed Aave source to the proposed Spoke runtime, nor provide the MetaExchange implementation, yvUSD runtime/configuration, or concrete parent Vault. This matters because the strategy grants MetaExchange unlimited swap-token allowances and relies on all three integrations for accounting and exits. Historical broadcast files concern earlier strategy implementations and do not prove deployment of the reviewed source.

### Recommendation

Before release, reproduce final runtime bytecode and constructor inputs; resolve proxy and administrative roles; verify Aave Spoke/Hub implementations and reserve configuration; inspect yvUSD’s queue, hooks, debt, and liquidity; verify MetaExchange routes and allowance safety; and exercise the actual parent Vault’s allocation and withdrawal queue.
