# Security Review — Curve Lender Borrower PSA-5

## [High] Hard-coded address can sweep lender principal

### Details

In `fcf7587`, `Strategy.sweep` (`src/Strategy.sol:382-388`) lets the fixed `GOV` address transfer every token except the collateral asset. This includes yvcrvUSD receipt shares—the strategy’s lent principal (`BaseLenderBorrower.sol:624-628,739-741`)—and crvUSD needed to repay Curve debt. A compromise or misuse of this address can remove all such assets from the strategy; no prepared evidence establishes that it is an authorized full-custody role.

### Recommendation

Remove the arbitrary sweep authority or permanently protect `borrowToken`, `lenderVault`, and every accounting/position token; restrict any rescue function to documented Yearn emergency governance.

## [Medium] Deposits during soft liquidation are locked despite remaining idle

### Details

`availableDepositLimit` remains positive during soft liquidation, so a user can deposit; `_supplyCollateral` then skips deployment because the position is liquidatable (`Strategy.sol:156-160`). The deposit remains idle, but `availableWithdrawLimit` unconditionally returns zero while soft-liquidated (`Strategy.sol:225-229`), preventing its redemption. `test_depositWhenInSL` already demonstrates the deposit path.

### Recommendation

Block deposits during soft liquidation, or return at least the strategy’s idle asset balance as withdrawable capacity while preserving the restriction on Curve-backed collateral.

## [Medium] Deployment flow disables negative-carry safeguards

### Details

The non-test deployment path enables both APR-ignore flags (`script/Deploy.s.sol:86-90`), making borrow APR return `0` and lender APR return `1` (`Strategy.sol:271-282`). The leverage and tend checks therefore cannot detect negative carry (`BaseLenderBorrower.sol:249-262,437-445`), allowing continued leverage until a later loss report; the pinned health check normally requires management intervention to accept a loss.

### Recommendation

Do not deploy with both checks disabled unless an independent, governed negative-carry controller provides equivalent protection. Verify configured flags and test a high-borrow-APR/low-lender-APR unwind.

## [Informational] PSA-5 route/oracle liveness remains unverified

### Details

PSA-5 derives final min-out from the LLAMMA oracle while executing through separate Curve routes. A route output more than the configured tolerance below that oracle will atomically revert reports or unwind swaps; this is protective behavior, but prepared evidence does not establish whether such divergence is realistic or operationally recoverable.

### Recommendation

Fork-test each WETH, wstETH, and WBTC route with adverse oracle/route divergence, covering `report`, debt repayment, and emergency recovery.

## [Informational] Deployment equivalence is unverified

### Details

The reviewed source is `fcf7587`, descended from PSA-5 commit `436c215`; prepared comments and broadcasts claim deployments, but no bytecode comparison, runtime role/flag read, parent-vault relationship, or external protocol state was verified.

### Recommendation

Before release, compare deployed runtime bytecode and constructor inputs to `fcf7587`, then verify roles, APR-ignore flags, exchange addresses, lender-vault configuration, and allocator-vault integration.
