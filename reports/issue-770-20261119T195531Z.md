# LayerZero OFT Strategy Review — Issue #770

## [Medium] Cross-chain reconciliation can omit or double-count principal

### Details

At final commit `3c050ab`, [origin accounting](https://github.com/Schlagonia/tokenized-cctp/blob/3c050ab6852b84018eaf953cf5def21fb99fe363/src/bases/BaseCrossChain.sol#L49-L109) adds local tokens to a remote snapshot without reconciling outstanding transfers. Returning 50 against 1,000 recorded assets can therefore appear as 1,050 before the reduced remote report arrives. An origin keeper report accepts this 5% false profit; with factory profit locking disabled, 40 shares can redeem for 42 instead of 40. Conversely, newer remote snapshots can erase undelivered deposits, causing false losses or blocked reports. Timestamp freshness does not establish transfer inclusion. LayerZero [credits tokens before separately executing compose](https://github.com/LayerZero-Labs/LayerZero-v2/blob/9c741e7f9790639537b1710a203bcdfd73b0b9ac/packages/layerzero-v2/evm/oapp/contracts/oft/OFTCore.sol#L240-L270), so delivery ordering cannot provide atomic reconciliation.

### Recommendation

Track outstanding transfers and acknowledge which transfers each snapshot includes. Reconcile returned capital before allowing affected reporting and share operations. Test delayed credit, failed/retried compose, intervening deposits and competing withdrawals through the actual Endpoint queue.

## [Medium] Outsiders can spend fee reserves and rebridge withdrawal liquidity

### Details

The deposit allowlist checks the share receiver, while [Tokenized Strategy accepts funds from any caller and deploys the entire idle balance](https://github.com/yearn/tokenized-strategy/blob/82806289f967590c4efbf6bc3d237e4e7f0a0966/src/TokenizedStrategy.sol#L954-L975). An outsider can deposit a small amount for an allowed parent, donating shares while triggering a bridge send paid from the strategy’s [ETH reserve](https://github.com/Schlagonia/tokenized-cctp/blob/3c050ab6852b84018eaf953cf5def21fb99fe363/src/bases/BaseOFT.sol#L85-L98). Repetition can exhaust reserves; one such deposit can also send returned withdrawal funds back remotely. This requires an accepted, share-minting deposit and positive bridge fees; practical attack cost depends on the actual bridge configuration.

### Recommendation

Authorize callers for reserve-funded bridging, charge its cost, or defer bridging to controlled maintenance. Reserve recalled liquidity from deposit-triggered deployment, and test deposits from an unrelated caller for an allowed receiver.

## [Medium] Unequal local decimals corrupt cross-chain report values

### Details

Both constructors validate only their local asset/OFT conversion rate. The remote [reports raw local asset units](https://github.com/Schlagonia/tokenized-cctp/blob/3c050ab6852b84018eaf953cf5def21fb99fe363/src/bases/BaseRemoteStrategy.sol#L106-L109), which the origin stores unchanged. LayerZero [converts token amounts between shared and local units](https://github.com/LayerZero-Labs/LayerZero-v2/blob/9c741e7f9790639537b1710a203bcdfd73b0b9ac/packages/layerzero-v2/evm/oapp/contracts/oft/OFTCore.sol#L326-L336), but does not convert this report payload. A valid six-decimal origin/eighteen-decimal remote pairing passes construction yet reports one token as `1e18` instead of `1e6`, normally blocking origin reporting through its health check. An actual USDG decimal mismatch is unproven.

### Recommendation

Normalize reports to an agreed denomination or enforce equal asset decimals across the pair. Test unequal-decimal OFTs and verify the intended USDG pair’s actual decimals.

## [Informational] USDG deployment, execution configuration and build remain unverified

### Details

Deployment addresses remain unspecified in the issue. Prepared upstream LayerZero source does not identify the deployed USDG/OFT implementations, spUSDG behavior or allocating parent vault. Zero-amount reporting compatibility, reciprocal peers, executor options, gas, fees and recovery remain unproved. The [round-trip test](https://github.com/Schlagonia/tokenized-cctp/blob/3c050ab6852b84018eaf953cf5def21fb99fe363/src/test/OFT.t.sol) simulates transport; it does not establish deployed behavior. The periphery Git pin and lock record disagree, and no reproducible Solidity build or deployed-bytecode comparison was established.

### Recommendation

Before funding, pin implementations and administrators, resolve dependency/build records, verify reciprocal factories, roles, decimals, peers, libraries/DVNs and both message-type options. Exercise zero-token reports, both withdrawal-send fees, partial redemption, shutdown, failed receive/compose and retry against the exact intended implementations and parent configuration.
