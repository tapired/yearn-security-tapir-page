# Security Review — Curve crvUSD Lender/Borrower New-Base Cutover

## [Medium] Fixed governance address can sweep lender principal and repayment assets

### Details

`Strategy.sweep()` permits the fixed `GOV` address to transfer any token except the collateral asset. This includes loose crvUSD and yvcrvUSD lender shares, both of which back the strategy’s Curve debt and user shares. Removing them can force collateral sales, prevent repayment, or realize losses.

The capability is restricted to an already privileged address, and no post-cutover deployment or ownership evidence establishes its live applicability.

### Recommendation

Prevent sweeping `asset`, `borrowToken`, and `lenderVault` shares. Prefer the strategy’s normal management authority and an explicit rescue-token allowlist over a separate fixed governance address.

## [Medium] Reports and tends can redeploy funds after shutdown

### Details

Tokenized Strategy intentionally leaves `report()` and `tend()` callable after shutdown. Both target hooks can reach `_leveragePosition()`, which supplies collateral and can create or increase Curve debt. Neither checks `isShutdown()`.

Consequently, a keeper call after an emergency withdrawal or other unwind can reopen the position and reintroduce liquidation exposure despite the irreversible shutdown flag.

### Recommendation

Add explicit shutdown branches to `_harvestAndReport()` and `_tend()`. Post-shutdown calls should only settle debt, account for value, and free assets; they must never create or increase a loan.

## [Medium] Soft-liquidation reporting omits LLAMMA value and can revert during settlement

### Details

The strategy detects soft liquidation through nonzero LLAMMA stablecoin `x`, but `balanceOfCollateral()` and final report accounting include only collateral `y`. Curve’s implementation shows that `x` is a distinct recoverable balance returned during full repayment. A successful report can therefore understate assets, record an artificial loss, distort share accounting, or fail the default loss health check.

There is also a liveness branch: when Curve debt exceeds lender and loose crvUSD by more than dust, `_settleDebt()` may call `remove_collateral()` to fund repayment. Curve rejects collateral removal while `x` is nonzero with `Already in underwater mode`, causing the report to revert when loose collateral is insufficient.

### Recommendation

Make reporting explicitly soft-liquidation aware. Either fully repay and unwind before reporting or consistently value both LLAMMA components against debt. Never attempt collateral removal while `x` is nonzero, and test both lender-surplus and lender-shortfall states.

## [Medium] Soft liquidation permits deposits while disabling all withdrawals

### Details

During soft liquidation, `availableWithdrawLimit()` returns zero, but `availableDepositLimit()` remains positive for an allowed receiver. The committed target test demonstrates that a deposit succeeds while soft-liquidated.

New capital can therefore enter an impaired position from which ERC-4626 withdrawals and redemptions are immediately unavailable, including through a configured parent Vault withdrawal queue.

### Recommendation

Return zero deposit capacity whenever soft liquidation disables withdrawals. If additional capital is required for recovery, accept it only through a dedicated privileged rescue mechanism that does not issue ordinary shares.

## [Medium] Supplied deployment flow disables both negative-carry safeguards

### Details

The non-test deployment script enables both APR-ignore flags. The strategy then represents Curve borrow APR as zero and lender reward APR as positive, making its tend and leverage comparisons retain or add debt even when borrowing is economically unprofitable.

The separate allocation APR oracle still compares real rates, but it does not restore the strategy’s internal exit and borrowing protections. No prepared evidence proves these flags are active on a post-cutover deployment.

### Recommendation

Do not enable both flags in production. Any temporary override should expire automatically, emit a prominent event, prevent debt increases while active, and trigger monitoring for negative realized carry.

## [Low] Hard liquidation leaves stale local state that blocks recovery

### Details

A full external Curve liquidation removes the loan, but the local `loanExists` flag remains true until management resets it. Subsequent deployment calls select `add_collateral()`, which Curve rejects because no loan exists.

The target’s committed test demonstrates zero external debt and collateral, remaining lender assets, positive advertised deposit capacity, blocked user redemption, and the need for manual flag repair before reporting.

### Recommendation

Treat `CONTROLLER.loan_exists()` as authoritative. Reconcile state before advertising deposit capacity or deploying funds, block deposits after liquidation, and report the loss safely before permitting a deliberate new loan.

## [Informational] MetaExchange authority and 50-basis-point execution viability are unverified

### Details

The strategy gives its immutable MetaExchange persistent unlimited allowances. The prepared evidence does not include that exchange’s implementation, proxy administration, or configured routes, so allowance abuse cannot be confirmed or excluded.

The base also defaults to a 50-basis-point oracle tolerance, while the repository’s fork setup raises it to 500 basis points because TriCRV fees and EMA lag require more room. Without the exact production routes and liquidity, ordinary report or unwind reverts at 50 basis points remain unresolved.

### Recommendation

Resolve and review the exact exchange runtime, administrators, venues, and routes. Approve only each swap’s required amount or revoke afterward, and test reports plus full and emergency withdrawals at production position sizes using the intended tolerance.

## [Informational] Post-cutover deployment and exact external composition are unverified

### Details

No prepared artifact proves that the reviewed post-cutover commit was deployed or identifies its concrete strategy, Controller blueprint, AMM, lender Vault, MetaExchange, parent Vault, roles, flags, limits, routes, and allowlists.

The issue-linked Curve Controller revision also has different `repay` and `remove_collateral` selectors from those used by the strategy. An older compatible revision has the relevant expected semantics, but Curve factory upgrades do not identify the blueprint used by an existing market.

### Recommendation

Before release, obtain creation transactions and runtime bytecode for every component, resolve proxies and Curve blueprints, compare code hashes and constructor arguments, and read back all roles, APR flags, LTV/slippage limits, allowlists, routes, oracle registrations, parent debt caps, and withdrawal queues.
