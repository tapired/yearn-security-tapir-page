# Yearn Automated Transmuter Strategy Security Review

## [Medium] Mutable auction floor enables privileged share-price dilution

### Details

Management can immediately change `minimumPrice`, which also values idle alAsset in `estimatedTotalAssets()`. With idle alAsset present, compromised management can report an artificial loss, admit deposits at the depressed share price, restore the floor, and report the recovery. A deterministic example transferred 45% of the legacy cohort’s value to an intervening depositor without any underlying economic change.

This requires management control, a health-check bypass, enabled deposits, sufficient Transmuter headroom, and idle rather than already-positioned alAsset.

### Recommendation

Decouple accounting valuation from mutable auction configuration. Use a bounded independent valuation or immutable acquisition value, and prevent deposits across valuation changes until accounting has been reconciled. Add a two-cohort dilution test.

## [Medium] Shutdown still permits new Transmuter positions

### Details

Shutdown prevents new asset auctions, but `_tend()` and `_transmutableAmount()` do not check shutdown. A keeper can therefore place idle alAsset into a fresh Transmuter redemption after shutdown, delaying recovery until maturity or exposing it to an early-exit fee. The checked-in shutdown test explicitly expects this behavior.

### Recommendation

Return zero from `_transmutableAmount()` during shutdown and prevent `_tend()` from creating new positions. Shutdown handling should only sweep auctions, claim existing positions, and redeem available MYT.

## [Medium] Auction pricing ignores transmutation fees and bad debt

### Details

The auction only requires a nominal alAsset-per-asset floor above par. Net recovery also depends on the mutable Transmuter fee and Alchemist bad-debt multiplier. Consequently, a stale floor can permissionlessly exchange sound asset for alAsset worth less after redemption.

For example, buying 1.1 alAsset per USDC with a 1% fee and 15% bad debt recovers only 0.92565 USDC, a 7.43% principal loss. Current live parameters were not available, so manifestation remains conditional.

### Recommendation

At every kick, require the floor’s fee- and bad-debt-adjusted recovery value to exceed the asset sold, including a safety margin. Pause auctions automatically when that invariant fails.

## [Medium] MYT adapter failures can block idle-only withdrawals

### Details

`availableWithdrawLimit()` always calls `MYT.convertToAssets()`, even with zero MYT and no mature positions. The exact Morpho Vault V2 implementation routes this through `accrueInterestView()`, which calls `realAssets()` on every configured adapter. Those concrete Alchemix adapters can call external vault views, so one reverting adapter can block withdrawals despite sufficient idle USDC.

The anchor fix catches failures in the later liquidity-limit probe only; replacing `mytLimits` does not contain this earlier path.

### Recommendation

Return the idle amount before interacting with MYT when there is no MYT or matured exposure. For nonzero exposure, catch valuation failures and conservatively expose only idle liquidity. Add a test with a reverting Morpho adapter and zero strategy MYT.

## [Low] Exact maximum withdrawals can fail by rounding dust

### Details

The withdrawal limit values MYT in assets, while `_freeFunds()` converts available assets to shares with down-rounding and then redeems those shares with another down-rounding. At a 1001:1000 asset/share ratio, an advertised 500-unit withdrawal selects 499 shares and returns only 499 units. A default zero-loss exact withdrawal can therefore revert at the advertised boundary.

### Recommendation

Base the advertised limit on the assets actually redeemable from the selected share count, or calculate the required shares with upward rounding while respecting the balance and liquidity cap.

## [Informational] Matured-claim shortfall handling remains unverified

### Details

The withdrawal limit assumes a matured position produces fee- and bad-debt-adjusted MYT. The concrete Transmuter can instead return part of a mature claim as synthetic alAsset when `debtPaid < scaledTransmuted`. The strategy ignores the claim return values, removes the position, and cannot convert that returned alAsset during the same withdrawal.

Alchemist locking, earmarking, repayment, and bad-debt rules may make a material mature shortfall unreachable, but the prepared tests do not establish that invariant.

### Recommendation

Add a stateful test covering concurrent redemptions, repayments, burns, allocator loss, and bad debt. Either prove mature `syntheticReturned` is zero within a documented rounding bound or reconcile returned alAsset before advertising and servicing the withdrawal.

## [Informational] APR oracle ignores the requested debt change

### Details

`aprAfterDebtChange()` ignores `_delta`, so current and marginal APR quotes are identical even when additional capital would encounter auction caps, insufficient Transmuter headroom, or a full position ladder. No prepared evidence shows an automated allocator currently consumes this oracle.

### Recommendation

Model the requested debt change and relevant capacity constraints, or do not register the oracle for automated allocation decisions.

## [Informational] Deployment and runtime equivalence are not established

### Details

The issue’s deployment table remains `TBD`. Prepared Alchemix evidence identifies a historical V3 source lineage, but neither it nor the mandatory deployments repository identifies this strategy’s deployed address or current bytecode. Current proxy implementations, adapters, allocations, roles, gates, fees, bad debt, auction settings, and shutdown state therefore remain unverified.

### Recommendation

Provide the strategy address and review block, then verify runtime bytecode, constructor immutables, proxy implementations, roles, gates, Morpho adapters, liquidity configuration, and all relevant Transmuter and auction parameters.
